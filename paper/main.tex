\begin{abstract}
Many SQL antipattern detectors analyse SQL statements. jOOQ instead constructs queries through Java domain-specific language expressions and generated schema classes. We evaluate a large language model (LLM)-based detector that returns class-labelled source spans and use its output to characterise flags in an identified open-source corpus. A size-stratified sample of 61 repositories yielded a single-annotator reference dataset of \num{1562} occurrences across 19 operationalised antipatterns; seven classes met the support criteria for detector analysis. Against the \num{523} original reference spans in a 20-repository, project-disjoint test partition, the selected Zero-Shot configuration with Claude Opus 4.5 achieved micro precision \num{0.858}, recall \num{0.880}, and F1-score \num{0.869}. Per-class F1 ranged from \num{0.481} to \num{0.974}. Across the 602-repository corpus, the detector produced \num{15931} flags in \num{601} repositories; Implicit Columns and ID Required accounted for \qty{68.3}{\percent} of them. The two leading Implicit Columns source-fragment patterns comprised \qty{71.7}{\percent} of that class's flags, while fragments matching \texttt{like(} comprised \qty{46.8}{\percent} of Poor Man's Search Engine flags. Agreement varied substantially by class. The corpus counts describe detector flags rather than prevalence or API-risk estimates.
\keywords{SQL antipatterns \and jOOQ \and large language models \and static analysis \and prompting \and empirical software engineering}
\end{abstract}
